# 原生CAD运行验收

日期：2026-11-08

摘要：以独立文档验证真实AutoCAD启动、原生实体、预览、DWG保存和重开；全部调用经过同一个stdio MCP会话，保留原有图纸。

## 执行

Windows已安装AutoCAD及本项目锁定依赖时，在技能目录运行：

```text
python scripts/verify_native.py --run-native --destination runtime/native-acceptance-001
```

destination必须是新目录。--run-native显式启用本次实机操作：没有运行实例时启动AutoCAD，已有实例时复用，建立独立测试图纸并保存测试DWG和原生预览。测试不改原有图纸中的实体、不关闭原有图纸、不取消命令、不结束AutoCAD。

测试使用持久MCP会话；连续执行不能拆成多次默认只读的CLI call。脚本本身不导入COM，不发送原始命令，不操作鼠标键盘。CAD服务在单独STA线程内调用ActiveX。

## 完整检查链

1. 检查显式启动条件，执行启动并验证操作重试不重复创建实例。
2. 记录已有文档与活动文档，创建独立毫米文档。
3. 生成跨零度的原生圆弧、圆、原生尺寸和测试文字，回读中心、半径、起止角与实际测量值。
4. 拒绝关闭未保存内容。导出原生WMF，检查实际绘制记录、渲染非空并保存PNG供查看。
5. 另存到新DWG路径，核对格式签名、哈希和新文档token；检查幂等重试及已有路径不覆盖。
6. 关闭保存后的独立文档，重新打开DWG，按原句柄比较实体与全部测量，再关闭测试文档。
7. 恢复原活动文档，检查原有文档集合保持不变。

输出native-acceptance.json记录每一步真实响应、文件哈希与失败位置。失败时不把后续未执行步骤记为通过；原始失败证据保留。通过表示该环境和本测试输入的原生链成立，不替代参考图的尺寸语义、字体和完整图面对照，也不代表某个宿主模型已经完成端到端任务。

## 客户交付的受信原生回读

活动图纸通过 `cad_delivery_snapshot` 获取完整原生事实，使用同一 MCP 服务实际 Open/Save/SaveAs 建立当前文件与文档的关联。快照需要已保存且 DBMOD=0，两次完整读取一致，文件 SHA 与当前磁盘相同。原生尺寸从实际定义点计算并核对匿名显示块；读取器错误仍保留，不能写入测量缓存冒充读回成功。当前实现限正 WCS XY 二维基础图元、普通线性/对齐尺寸及连续线型；未知对象或属性拒绝，不推断全行业支持。

要求最终关闭重开时，以 `dwg_lifecycle` 检查同服务 Save/SaveAs→本会话有归属且干净的 Close→相同 SHA 的真实 Open。离线日志、冷附着、只保存或仅文件存在不能建立该生命周期。检查并不构成任意保存、关闭客户图纸的授权。

严格只读的原生 WMF 导出可能仅覆盖当前视口。若覆盖不足，不能为了检查而悄悄 Zoom、修改系统变量或自动保存。存在原始 DXF 时，`cad_native_correspondence_preview` 比较全部模型实体、原生尺寸及匿名/箭头块、样式与物理字体，再由匹配的回读数据生成完整范围 PNG。记录同时绑定 DWG、原始 DXF、事实和图像 SHA；它是原生数据对应后的离线渲染，不是 AutoCAD 原生打印。PDF 还须独立比较实际物理描边及比例，不能仅检查页面出现过某种线宽。

完整对应预览、尺寸线继承及实际描边检查的细节见 [原生对应实现](../src/luomu_cad/native_correspondence.py)和[纸面描边读取](../src/luomu_cad/pdf_strokes.py)。最终 `workbench_delivery` 必须在持有受信文档的活动服务中重读；独立代理的 JSON 不会恢复或替代该内存上下文。

## 断线与操作归属

AutoCAD明确返回RPC忙拒绝时，服务只重试对应的被拒绝步骤。Add/Open已返回的文档先等待只读接口就绪，不能重复创建。创建或打开后的身份检查点用于同operation_id恢复，未知结果仍依据日志回读，不按文件名猜测归属。

文档名称、应用窗口及文档窗口共同用于恢复检查。打开旧文档不会使它成为可任意关闭的对象；关闭保护以当前会话实际创建/打开的归属和Saved状态为依据。
